## [0.2.0] - 2026-10-12

First tagged release. It covers the initial public commits plus the work below.

### Added

- **Body schemas from HAR.** JSON request and response bodies become JSON Schemas per status code, with required keys, nullable fields, and id-keyed maps as `additionalProperties`.
- **Confidence per operation.** `1 − 0.5^seen`, capped at 0.99. It's exported as `x-contour-seen` / `x-contour-confidence` and copied into each SDK method's doc comment.
- **Gaps.** The model lists operations seen only once, missing 4xx/5xx responses, merged hosts, TLS left closed, and what PCAP mode cannot read.
- **Typed SDKs.** `client.ts` exports request/response types and `client.py` uses `TypedDict`. Local `$ref`, `enum`, `oneOf`/`anyOf`/`allOf`, `nullable` and `additionalProperties` are supported. Both pass `tsc --strict` and `mypy --strict` in CI.
- **CLI.** New `--openapi PATH`, `--host`, `--version` options and a per-operation summary table. `python3 -m contour` works without installing.
- Static assets (`.js`, `.css`, images, fonts) and non-http(s) URLs (`data:`, `blob:`) are skipped.
- `examples/sample.har` (a fictional orders API) and its committed output in `examples/output/`, with a test that fails if the output drifts from the code.
- `docs/export-a-har.md`, `SECURITY.md`, CI on Python 3.10–3.13, and issue templates.

### Changed

- scapy is now an optional extra (`pip install '.[pcap]'`). The HAR → OpenAPI → SDK path uses the standard library only. The unused `pydantic` dependency was removed.
- Model: `stats.packets` is renamed to `stats.records`. New fields: `stats.skippedStatic`, and per-endpoint `confidence`, `requestSchema` and `responseSchemas`. CLI and model text is now in English.
- Generated method names include path parameters (`get_v1_orders_by_id`). Generated files carry a "Generated by Contour" header.

### Fixed

- `GET /orders` and `GET /orders/{id}` produced the same method name. In Python the second silently replaced the first, and in TS it was a duplicate member.
- Query parameters named `from`, `class`, `page[size]` and similar produced a `client.py` that did not compile.
- Repeated ids in one path produced duplicate `{id}` parameters. They are now `{id}`, `{id2}`, and so on.
- Short prefixed ids (`ord_1`) were not templated, while words such as `/payment_methods` were.
- Path parameters were not declared in the OpenAPI, which made the spec invalid.
- PCAP-only operations claimed a `200` response that had never been observed.
- `secretsSeenInSource` was always 0 for PCAP input.
- A HAR with a UTF-8 BOM, JSON that is not a HAR, or a random file now give a clear error and exit code 1, instead of a traceback.
- A summary ending in `"` broke the generated Python docstring.

### Security

- Body values never enter the model. Keys that look like secrets are dropped and reported.
- Path parameters are URL-encoded in both generated clients.
- Hostile spec content (quotes, backticks, `${}`, `*/`, U+2028) cannot inject code into a generated client. A test covers it.
